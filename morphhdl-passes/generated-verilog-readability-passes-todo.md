# Generated-Verilog readability passes roadmap

This file is the controlling implementation checklist for exactly two
appearance/readability passes over already generated Verilog:

1. generated-Verilog internal signal-name rewriting; and
2. Verilog formatting/pretty-printing.

No optimization pass is authorized by this roadmap.

## Fixed scope and non-goals

- The input is Verilog already generated by SpinalHDL or MorphHDL.
- The output must have the same RTL behavior as the input.
- These passes may improve names and textual presentation only.
- They must not recover, recreate or infer code eliminated during Scala
  elaboration.
- They must not reconstruct parameter intent from concrete constants or signal
  naming patterns.
- They must not alter parameters, parameter expressions, widths, signedness,
  literals, operators, sensitivity lists, clock/reset behavior, assignment
  scheduling, procedural statement order, generate structure, hierarchy,
  memory behavior or library algorithms.
- Signal-name rewriting may use parsed declarations, references, scopes,
  existing identifiers and available source metadata only to choose names. It
  must not identify or reconstruct component behavior from names.
- Formatting/pretty-printing must preserve declaration order, module-item order,
  procedural statement order, comments and attributes.
- Module names, instance names, port names, parameter names, local-parameter
  names and generate-block labels are outside the signal-name pass. Only
  internal nets, variables/registers and generated temporary signals are in
  scope.
- No third pass may be added without an explicit reviewed update requested by
  the user.

## Isolation boundary

All implementation source, tests, fixtures, build configuration and generated
artifacts for this roadmap must live under the standalone top-level
`morphhdl-passes/` workspace.

The workspace must:

- use its own nested SBT and/or Mill build;
- not be added to the repository root SBT/Mill aggregate;
- not modify upstream-owned SpinalHDL source under `core/`, `lib/`,
  `idslplugin/`, `idslpayload/`, `sim/` or `tester/`;
- not place source in a `spinal.*` package;
- not require a Git submodule;
- consume generated Verilog through a structured parser/IR rather than regex
  replacement; and
- fail closed when it encounters unsupported syntax or an unresolved symbol.

A uniquely named MorphHDL-owned GitHub workflow file may be added solely to run
this standalone workspace. No existing upstream workflow or root build file may
be modified for these passes.

## Dependency and execution discipline

- Only one readability-pass increment is implemented at a time.
- Only the first unchecked increment whose dependencies are all implemented and
  merged into `parameterized-verilog` is eligible to start.
- A dependency on `PV-N` refers to Increment N in
  `docs/morphhdl/parameterized-verilog-todo.md` on the target branch.
- A dependency is satisfied only when its checkbox is `[x]` on
  `parameterized-verilog`; an implementation branch or open pull request does
  not satisfy it.
- If a requested increment is marked `BLOCKED`, the implementation request must
  be rejected with the exact unsatisfied dependency or dependencies recorded
  below. Work must not silently skip, partially implement or substitute another
  increment.
- An increment checkbox changes to `[x]` only in the increment's reviewed pull
  request after all required gates pass. The next increment's `Status` line is
  updated in the same pull request.
- Every pass must be deterministic and idempotent: repeated execution with the
  same input and configuration produces byte-identical output, and a second
  execution produces no further change.

## Incremental plan

- [ ] **RP-01 — Isolated readability-pass workspace and boundary guard**

  **Dependencies:** none.

  **Status:** `READY` after this roadmap pull request is merged.

  Create the standalone `morphhdl-passes/` build and test workspace without
  changing repository root build files or upstream-owned SpinalHDL source. Add
  a boundary check that rejects pass-increment changes outside
  `morphhdl-passes/`, except for this roadmap and one uniquely named pass
  workflow. Establish the shared pass result, diagnostic and configuration
  contracts needed only by the two passes in this file; do not implement any
  transformation yet.

- [ ] **RP-02 — Structured Verilog-2001 parse and round-trip foundation**

  **Dependencies:** RP-01 implemented and merged.

  **Status:** `BLOCKED` by RP-01.

  Parse the strict Verilog-2001 constructs exercised by current SpinalHDL and
  MorphHDL generated RTL into a fresh, MorphHDL-owned structured IR with
  declaration/reference resolution and lexical scope. Preserve comments,
  attributes and source ordering needed by the two readability passes. Re-emit
  an unchanged design without semantic or structural modification and reject
  unsupported or ambiguous input explicitly. This increment must not infer
  missing elaboration-time alternatives or parameter intent.

- [ ] **RP-03 — Readability-pass equivalence and determinism gates**

  **Dependencies:** RP-02 implemented and merged.

  **Status:** `BLOCKED` by RP-02.

  Add the common validation gates used by both requested passes. The gates must
  prove resolved-IR equivalence after canonicalizing only permitted name and
  whitespace differences, verify strict Verilog-2001 compilation, exercise
  representative generated RTL through existing behavioral simulations where
  applicable, and detect any change to parameters, expressions, widths,
  signedness, hierarchy, generate/process structure, statement order,
  clock/reset behavior or memory behavior. Add repeated-run determinism and
  idempotence checks.

- [ ] **RP-04 — Generated-Verilog internal signal-name rewriting pass**

  **Dependencies:** RP-03 implemented and merged.

  **Status:** `BLOCKED` by RP-03.

  Implement the first requested pass. Rename only eligible internal nets,
  variables/registers and generated temporary signals through resolved symbol
  identities, updating every reference in the correct lexical scope. Produce
  legal, readable, deterministic and collision-free identifiers while retaining
  already suitable names. Keep all public names and all out-of-scope identifiers
  unchanged. The pass must not use a signal name to infer component type,
  algorithm or parameterized behavior. Close the increment only after the RP-03
  gates prove that renaming is alpha-equivalent and behavior-preserving.

- [ ] **RP-05 — Verilog formatting/pretty-printing pass**

  **Dependencies:** RP-04 implemented and merged.

  **Status:** `BLOCKED` by RP-04.

  Implement the second requested pass. Re-emit the structured Verilog IR with
  deterministic indentation, spacing, line breaks, continuation layout and
  consistent presentation of declarations, expressions, module instances,
  generate regions and procedural blocks. Preserve every identifier delivered
  by the signal-name pass and preserve declaration order, module-item order,
  procedural statement order, comments and attributes. Do not simplify,
  regroup, reorder or optimize RTL. Close the increment only after the RP-03
  gates prove that the change is formatting-only and behavior-preserving.

- [ ] **RP-06 — Combined two-pass standalone pipeline and regression closure**

  **Dependencies:** RP-05 implemented and merged.

  **Status:** `BLOCKED` by RP-05.

  Provide one plug-and-play file-to-file entrypoint inside `morphhdl-passes/`
  that can enable either pass independently or run the signal-name pass followed
  by the formatting pass. Validate concrete SpinalHDL output and the currently
  available MorphHDL parameterized-Verilog output. Prove deterministic,
  idempotent, strict-Verilog-2001 and behavioral equivalence for individual and
  combined operation. This entrypoint must contain only the two passes defined
  in this roadmap.

- [ ] **RP-07 — Final MorphHDL generated-source handoff**

  **Dependencies:** RP-06 and PV-48 implemented and merged.

  **Status:** `BLOCKED` by RP-06 and PV-48.

  Connect the completed standalone two-pass pipeline to the final MorphHDL
  single-source generation result as an optional post-generation handoff, while
  keeping all pass implementation and build ownership under `morphhdl-passes/`.
  Do not modify upstream-owned SpinalHDL source or repository root build files.
  Keep the readability pipeline disabled by default so existing generation is
  unchanged unless explicitly enabled. Validate both legacy concrete Verilog
  and the final parameterized-Verilog production path. No optimization,
  semantic reconstruction or additional pass is in scope.

## Completion target

This roadmap is complete at RP-07. Completion means the two requested passes can
optionally transform generated Verilog into more readable, consistently
formatted RTL while retaining the same behavior, without modifying
upstream-owned SpinalHDL source and without adding any optimization or semantic
reconstruction pass.
